# Инструкция по миграции на модульную архитектуру

## 📋 Краткая инструкция

### Шаг 1: Копирование файлов
Скопируй все файлы из проекта в папку `src/` твоего PlatformIO проекта:

```
src/
├── main.cpp
├── config.h
├── types.h
├── app_state.h
├── app_state.cpp
├── matrix_keyboard.h
├── matrix_keyboard.cpp
├── keyboard_map.h
├── midi_helpers.h
├── midi_helpers.cpp
├── ble_midi_handler.h
├── ble_midi_handler.cpp
├── display.h
├── display.cpp
├── menu_logic.h
├── menu_logic.cpp
├── play_mode.h
└── play_mode.cpp
```

### Шаг 2: Обновление platformio.ini
Скопируй содержимое `platformio.ini` из рефакторинга в твой файл

### Шаг 3: Компиляция
```bash
pio build
```

Всё должно скомпилироваться без ошибок.

## 📝 Что изменилось в коде?

### Было (main.cpp ~900 строк):
```cpp
void setup() {
    // 50 строк инициализации
}

void loop() {
    // сканирование матрицы
    // обработка меню
    // обработка игры
    // рисование
    // всё в одной функции...
}

// функции для матрицы (100+ строк)
// функции для BLE MIDI (100+ строк)
// функции для рисования UI (200+ строк)
// глобальные переменные (50+ строк)
// всё в одном файле...
```

### Стало (модульная архитектура):
```
config.h              ← константы
types.h               ← типы
app_state.h/cpp       ← состояние
matrix_keyboard.h/cpp ← матрица
keyboard_map.h        ← раскладка
midi_helpers.h/cpp    ← MIDI
ble_midi_handler.h/cpp ← BLE
display.h/cpp         ← UI
menu_logic.h/cpp      ← меню
play_mode.h/cpp       ← игра
main.cpp              ← setup + loop (только 90 строк!)
```

### Преимущества:
- **90 строк main.cpp** вместо 900 - легко читать
- Каждый модуль отвечает за одно - легко редактировать
- Все параметры в config.h - легко находить
- Каждая функция на своём месте - легко ориентироваться

## 🎯 Часто задаваемые вопросы

### Q: Будет ли работать с M5Stack Cardputer?
**A:** Да, 100%. Все API M5Cardputer остались без изменений.

### Q: Нужно ли менять пины?
**A:** Нет, пины те же, они в `config.h` констант `SR_*`.

### Q: Могу ли я добавить новую функцию?
**A:** Да, очень просто:
1. Добавь новый .h файл (или расширь существующий)
2. Напиши функции
3. Вызови её из `main.cpp::loop()`

### Q: Как добавить новый пункт в меню?
**A:** 
1. Добавь в `types.h::MenuItemID` перечисление
2. Добавь в `ble_midi_handler.h::BLE_PWR_TABLE` метку
3. Добавь обработку в `menu_logic.cpp::handleMenuInput()`
4. Добавь отрисовку в `display.cpp::drawMenu()`

### Q: Почему используется `g_` префикс для глобальных переменных?
**A:** Чтобы было видно, что это глобальная переменная, а не локальная. Это улучшает читаемость.

### Q: Могу ли я удалить какой-то модуль?
**A:** 
- Если матрица не нужна: удали `matrix_keyboard.h/cpp` и убери вызов `scanMatrixKeyboard()` из loop
- Если BLE не нужен: удали `ble_midi_handler.h/cpp` (но это усложнит код)
- Удалять нельзя: `config.h`, `types.h`, `app_state.h/cpp`, `main.cpp`

## 🐛 Если что-то не работает

### Ошибка: "undefined reference to `..."
- Убедись, что копировал **оба** файла (.h и .cpp)
- Если скопировал только .h - функции не реализованы

### Ошибка: "ambiguous overload"
- Скорее всего, дублируется определение переменной
- Проверь, нет ли дублей в app_state.cpp

### Ошибка компиляции при включении
- Убедись, что в .h файлах нет циклических зависимостей
- Текущие зависимости безопасны:
  - config.h → types.h
  - types.h → config.h
  - app_state.h → types.h + config.h
  - остальное → app_state.h

### Программа компилируется, но не работает
- Проверь: включены ли все инициализирующие функции в setup()?
- Проверь: вызывается ли основная функция в loop()?
- Запусти Serial Monitor (115200 бод) и посмотри логи
