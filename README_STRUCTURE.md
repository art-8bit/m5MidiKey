# Структура проекта Cardputer MIDI Keyboard (рефакторинг)

## Обзор

Проект был рефакторизирован из монолитного `main.cpp` (~800 строк) в модульную архитектуру с 9 отдельными модулями, каждый отвечает за свою задачу.

---

## 📁 Структура файлов

```
src/
├── main.cpp                    ← ГЛАВНЫЙ ФАЙЛ (только setup + loop)
│
├─── КОНФИГУРАЦИЯ И ТИПЫ ───
├── config.h                    ← Все константы, цветовая палитра, пины
├── types.h                     ← Перечисления (AppMode, MenuItemID, KeyboardSource)
├── app_state.h / app_state.cpp ← Глобальное состояние приложения
│
├─── АППАРАТУРА И ВВОД ───
├── matrix_keyboard.h/cpp       ← Матричная клавиатура (74HC595 + 74HC165)
├── keyboard_map.h              ← Маппинг встроенной клавиатуры
│
├─── MIDI И ЗВУК ───
├── midi_helpers.h/cpp          ← Вспомогательные функции (midiNote, noteLabel)
├── ble_midi_handler.h/cpp      ← BLE MIDI управление (callbacks, power, panic)
│
├─── ИНТЕРФЕЙС ───
├── display.h/cpp               ← Рисование UI (статусбар, меню, пиано)
├── menu_logic.h/cpp            ← Логика обработки меню
├── play_mode.h/cpp             ← Логика режима игры (встроенная + матрица)
│
└── platformio.ini              ← Конфиг PlatformIO
```

## 📚 Детальное описание каждого модуля

### 1. **config.h** (конфигурация)
Содержит все жёсткие константы:
- Размеры экрана (240x135)
- Цветовая палитра RGB565
- Пины сдвиговых регистров
- Размеры матрицы (4 строки × 10 столбцов)
- Маппинг матрицы → MIDI ноты
- Параметры MIDI (диапазоны октав, скорость, каналы)

**Когда редактировать**: изменение пинов, цветов, размеров матрицы

---

### 2. **types.h** (типы)
Перечисления и структуры:
- `AppMode` - режимы приложения (MENU, PLAY)
- `MenuItemID` - пункты меню (OCTAVE, VELOCITY, BLE_POWER и т.д.)
- `KeyboardSource` - источник клавиатуры (BUILT_IN, MATRIX, BOTH)
- `BLEPwrEntry` - таблица уровней мощности
- `NoteKey` - маппинг клавиши на MIDI

**Когда редактировать**: добавление новых пунктов меню или режимов

---

### 3. **app_state.h/cpp** (глобальное состояние)
**app_state.h**: Объявления всех глобальных переменных
- `g_appMode` - текущий режим
- `g_bleConnected` - статус BLE
- `g_needRedraw` - флаг перерисовки
- `g_octave`, `g_velocity`, `g_midi_ch` - настройки
- `g_key_state[]` - состояние всех клавиш
- И многое другое...

**app_state.cpp**: Определения и инициализация

**Когда редактировать**: добавление новых глобальных переменных

---

### 4. **matrix_keyboard.h/cpp** (матричная клавиатура)
Управление сдвиговыми регистрами 74HC595/74HC165:
- `initShiftRegisters()` - инициализация GPIO
- `shiftOut595()` - отправка данных в выходной регистр
- `shiftIn165()` - чтение входного регистра
- `scanMatrixKeyboard()` - полное сканирование матрицы
- `getMatrixKey()` - получить состояние одной ячейки

**Когда редактировать**: изменение алгоритма сканирования или частоты

---

### 5. **keyboard_map.h** (маппинг встроенной клавиатуры)
Только данные (массивы констант):
- `WHITE_KEYS[]` - клавиши A-S-D-F-G-H-J-K-L-;
- `BLACK_KEYS[]` - клавиши W-E-T-Y-U-O-P
- `BK_POS[]` - горизонтальные позиции чёрных клавиш

**Когда редактировать**: изменение раскладки клавиатуры

---

### 6. **midi_helpers.h/cpp** (вспомогательные функции MIDI)
Простые, часто используемые функции:
- `midiNote(rel)` - перевести смещение в MIDI номер
- `noteLabel(midi)` - получить имя ноты (например "C#4")
- `anyKeyPressed()` - проверить, нажата ли какая-то встроенная клавиша

**Когда редактировать**: редко меняется, только для расширения функциональности

---

### 7. **ble_midi_handler.h/cpp** (BLE MIDI)
Управление BLE соединением и отправкой MIDI:
- `onBleConnected()` - callback при подключении
- `onBleDisconnected()` - callback при отключении
- `applyBlePower()` - установить уровень мощности TX
- `panicAllNotesOff()` - отправить All Notes Off на все каналы
- `BLE_PWR_TABLE[]` - таблица уровней мощности

**Когда редактировать**: изменение поведения BLE или уровней мощности

---

### 8. **display.h/cpp** (рисование UI)
**display.h**: Объявления функций рисования

**display.cpp**: Реализация:
- `drawStatusBar()` - верхняя полоса (название, октава, батарея, BLE)
- `drawMenu()` - экран меню с пунктами и значениями
- `drawPlay()` - экран игры с пианино и информацией о ноте
- `redraw()` - полная перерисовка экрана

**Когда редактировать**: изменение дизайна, добавление элементов интерфейса

---

### 9. **menu_logic.h/cpp** (логика меню)
Обработка нажатий клавиш в режиме MENU:
- `handleMenuInput(now)` - навигация по меню (I/K) и изменение значений (J/L)

Все логи обработки I, K, J, L клавиш находятся здесь.

**Когда редактировать**: изменение навигации или логики выбора параметров

---

### 10. **play_mode.h/cpp** (логика режима игры)
Обработка обеих клавиатур в режиме PLAY:
- `handleBuiltInKeyboard()` - встроенная Cardputer клавиатура
- `handleMatrixKeyboard()` - матричная клавиатура (74HC595 + 74HC165)
- `handlePlayMode()` - главная функция, объединяющая обе

**Когда редактировать**: изменение поведения игры, добавление эффектов

---

### 11. **main.cpp** (главный файл)
**Только 3 функции**:
1. `setup()` - инициализация
2. `loop()` - основной цикл
3. Импорты всех модулей в начале

Очень читаемо! Видна вся логика потока программы.

---

## 🎯 Как редактировать проект

### Нужно изменить цвет экрана?
→ Отредактируй `config.h` (константы `C_*`)

### Нужна новая клавиша в меню?
→ Добавь в `types.h` (MenuItemID), затем логику в `menu_logic.cpp`

### Нужна новая матрица размером 5×8?
→ Измени `config.h` (MATRIX_ROWS, MATRIX_COLS, MATRIX_MAP)

### Нужно изменить алгоритм сканирования матрицы?
→ Отредактируй `matrix_keyboard.cpp` (функция `scanMatrixKeyboard()`)

### Нужно другое распределение белых/чёрных клавиш?
→ Отредактируй `keyboard_map.h` (WHITE_KEYS, BLACK_KEYS, BK_POS)

### Нужно изменить визуальное оформление?
→ Отредактируй `display.cpp` (функции `drawMenu()`, `drawPlay()`)

### Нужно иное поведение в режиме меню?
→ Отредактируй `menu_logic.cpp` (функция `handleMenuInput()`)

### Нужна новая функциональность в игре?
→ Отредактируй `play_mode.cpp` (добавь функцию, вызови из `handlePlayMode()`)

## 🔍 Примеры навигации по коду

### "Как отправляется MIDI нота?"
1. `play_mode.cpp` - функция `handleBuiltInKeyboard()`
2. Вызывает `MIDI.sendNoteOn(mn, g_velocity, g_midi_ch)`
3. `mn` вычисляется в `midi_helpers.h: midiNote(rel)`
4. `rel` берётся из `keyboard_map.h: WHITE_KEYS[].rel`

### "Как работает меню?"
1. `main.cpp::loop()` вызывает `handleMenuInput()`
2. `menu_logic.cpp` обрабатывает I/K/J/L/Enter
3. Изменяет глобальные переменные (`g_octave`, `g_velocity` и т.д.)
4. Устанавливает `g_needRedraw = true`
5. `main.cpp::loop()` вызывает `redraw()`
6. `display.cpp::drawMenu()` рисует обновлённый экран

### "Как сканируется матричная клавиатура?"
1. `main.cpp::loop()` вызывает `scanMatrixKeyboard()`
2. `matrix_keyboard.cpp` проходит по строкам
3. Для каждой строки: `shiftOut595()` активирует строку, `shiftIn165()` читает столбцы
4. Возвращает `matrixChanged = true` если состояние изменилось
5. `play_mode.cpp::handleMatrixKeyboard()` обрабатывает изменения
6. Отправляет MIDI ноты

## ✅ Преимущества этой архитектуры

1. **Читаемость**: каждый файл небольшой, можно понять за 5 минут
2. **Поддерживаемость**: изменение в одном модуле не влияет на другие
3. **Расширяемость**: просто добавляй новые функции в нужный модуль
4. **Тестируемость**: можно писать unit-тесты для отдельных модулей
5. **Командная разработка**: разные люди могут работать над разными модулями
6. **Переиспользование кода**: модули можно переиспользовать в других проектах
